## Tool names

Tools are advertised as `erebine.<group>.<verb>`, for example `erebine.intelligence.brief`. Your client may show them sanitized and namespaced -- Claude Code as `mcp__erebine__erebine_intelligence_brief`, opencode as `erebine_erebine_intelligence_brief`, Cline as `erebine__erebine_intelligence_brief_fc26e278`. Match on the `erebine_<group>_<verb>` part, whatever prefix or suffix your client adds.

## Recall before you work

This workspace remembers. Before starting any non-trivial task, find out what it already knows -- otherwise you will re-derive decisions that were made months ago, or contradict them.

- `erebine.intelligence.brief` -- project state. The default opening move on an unfamiliar task.
- `erebine.intelligence.decisions` -- what was already decided, and why. Check before proposing an approach.
- `erebine.memory.recall` / `erebine.memory.search` -- whenever the user refers to something as already discussed ("like we said", "the usual way", "that bug from last week"). Do not ask them to repeat it; look it up.
- `erebine.artifact.list` / `erebine.artifact.read` -- whenever the user mentions a saved doc, spec, or design.

If a tool answers the question, do not ask the user. Asking the user for context the workspace already holds is the failure this server exists to prevent.

## Save as you go

Persist insight at the moment it emerges, not at the end of the session. A session that ends abruptly loses everything you were holding to save later.

- `erebine.intelligence.track_decision` -- a load-bearing choice. Record the outcome, the reasoning, and the alternatives you rejected. A decision without its reasoning is not reusable.
- `erebine.intelligence.track_milestone` -- a completed piece of work.
- `erebine.memory.save` -- facts, constraints, user preferences, and hard-won gotchas that should survive into future sessions.

Save what is load-bearing and NOT recoverable from the code: rationale, rejected alternatives, constraints, preferences, the trap you just fell into. Do not save what the repository already records -- file structure, what a function does, git history.

Do not ask the user "should I save this". If it is load-bearing, save it.

## Other rules

1. Each read returns a stable snapshot. Re-issue a call only when its arguments differ meaningfully -- an identical repeat call spends a turn and returns the same bytes.

2. Supply every parameter in a tool's `required` list. A call that omits one is rejected.

3. Web research, GitHub code reads, and arithmetic go through `erebine.research.*`, `erebine.code.*`, and `erebine.calc.evaluate` rather than training-data recall.

4. `erebine.exec.*` touches the execution-plane mesh. It surfaces an approval URL when destructive; respect that and wait for human approval before continuing.

5. When you create a git commit that was generated by Erebine endpoints, use `Assisted-by: Erebine.ai [model-name/endpoint-name]` in the commit message footer so that we appropriately claim AI usage.

## Prompts

- `session.init` -- prime a session with one keystroke. No arguments.
- `brief` -- intelligence brief plus the 5 most recent decisions. No arguments.
- `onboard` -- curated context pack for a topic. Requires `topic`.
- `save-this` -- fill-in form pre-populated with a note. Requires `note`.
- `mcp-loop` -- toggle this workspace's MCP guidance-evolution loop, or read its status. Optional `mode`: on | off | status.
- `erepress` -- toggle this workspace's in-path token compression, or read its status. Optional `mode`: on | off | status.

The invocation form is client-specific: Claude Code uses `/mcp__erebine__<name>`, colon-style clients (Cursor, opencode) use `/erebine:<name>`, and mention-style clients use `@erebine <name>`. Arguments are supplied through the client's prompt-argument flow, not a bare space after the name; pi is the exception and takes the whole command tail as the argument.

## Resources

- `erebine://workspace/current/brief` -- the always-current brief.
- `erebine://workspace/current/recent-decisions` -- rolling decisions feed. Accepts `?since=7d` and `?limit=20`.
- `erebine://memory/{slug}` -- read a single memory by slug.
- `erebine://artifact/{id}` -- read a single artifact by id.

Prefer attaching a resource via `@`-mention over calling a tool when the goal is to cite, not to act.
